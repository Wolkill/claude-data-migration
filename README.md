# claude-data-migration

Перенос данных **Claude Code** и **Claude Desktop** с одного компьютера на другой — с историей диалогов, скиллами и настройками.

*[English version](README.en.md)*

Инструмент появился из реальной задачи: рабочий ноутбук отправлялся на форматирование, а на нём остались десятки сессий Claude Code, личные скиллы и проектные настройки. Всё это лежит в разных местах, часть — внутри рабочих папок проектов, и вручную ничего не потерять сложно.

Ключевое свойство: на принимающей машине выполняется **слияние, а не замена**. Если там уже есть свои проекты и история, они не пострадают.

---

## Что переносится

| Что | Откуда | Примечание |
|---|---|---|
| История диалогов Claude Code | `~/.claude/projects/` | главное; JSONL-транскрипты |
| Личные скиллы, агенты, команды | `~/.claude/{skills,agents,commands,hooks,todos}` | |
| Плагины и маркетплейсы | `~/.claude/plugins/` | |
| Глобальный конфиг | `~/.claude.json` | сливаются только записи `projects` |
| Настройки и сессии десктопа | `%APPDATA%/Claude/` | MCP-конфиг, сессии Cowork |
| **Проектные** скиллы и настройки | `<проект>/.claude/`, `CLAUDE.md`, `.mcp.json` | лежат внутри рабочих папок |
| Рабочие папки проектов | пути из `~/.claude.json` | опционально, флагом |

### Что намеренно НЕ переносится

- **`~/.claude/.credentials.json`** — токен авторизации. На новой машине нужно просто войти в аккаунт.
- **Кэши** — `Cache`, `GPUCache`, `blob_storage`, `Network`, `vm_bundles` и подобное. Это легко несколько гигабайт мусора.
- **`AppData/Local/AnthropicClaude`** — это сама программа, а не данные. Переустанавливается.
- **Чаты claude.ai** — они хранятся на сервере и подтянутся сами после входа в аккаунт.

## Требования

- Windows
- **Python 3.8+** — основной путь. Только стандартная библиотека, ничего доустанавливать не нужно.
- PowerShell 5.1 — запасной вариант сбора, если Python на старой машине нет.

Интерфейс скриптов русскоязычный.

## Как пользоваться

### На старой машине (источник)

Скопируй туда `collect_claude.py`, `COLLECT.bat`, `COLLECT-FULL.bat` и запусти двойным кликом:

- **`COLLECT.bat`** — только история и настройки Claude
- **`COLLECT-FULL.bat`** — то же плюс сами рабочие папки проектов (нужно, если машину форматируют)

Оба сначала показывают объём и просят подтверждения. На выходе — `claude-evac.zip`.

Из командной строки доступны флаги:

```bash
python collect_claude.py --dry-run                 # только посчитать объём
python collect_claude.py --zip                     # собрать и упаковать
python collect_claude.py --zip --include-workdirs  # плюс рабочие папки
python collect_claude.py --profile "E:/Users/Имя"  # с подключённого диска
```

Последний вариант полезен, если старая машина не загружается: подключаешь её диск и читаешь профиль напрямую.

### На новой машине (приёмник)

1. Распакуй `claude-evac.zip` рядом со скриптами, чтобы получилась папка `claude-evac`
2. **`RESTORE-PROJECTS.bat`** — разложит рабочие папки проектов по их настоящим путям
3. **Полностью закрой Claude**, включая значок в трее
4. **`MERGE.bat`** — вольёт историю, скиллы и настройки

Оба `.bat` сначала делают пробный прогон, показывают план и ждут подтверждения.

## Что важно понимать

### Путь проекта зашит в имя папки с историей

Claude Code хранит транскрипты в папках, имя которых получается из пути проекта заменой всех не-буквенно-цифровых символов на дефис:

```
C:\Projects\my-app      ->  C--Projects-my-app
D:\work\demo_service    ->  D--work-demo-service
```

Преобразование необратимо (`_`, пробел и `\` дают одинаковый результат), поэтому настоящие пути берутся из ключей `projects` в `~/.claude.json` и сохраняются в `projects-map.csv`.

**Следствие:** на новой машине проекты должны лежать по тем же путям, иначе история к ним не привяжется. `RESTORE-PROJECTS.bat` делает это автоматически.

### Claude нужно закрыть перед слиянием

Приложение держит `~/.claude.json` в памяти и перезаписывает его при выходе — молча затирая влитые данные. `MERGE.bat` проверяет это и отказывается работать, если процесс запущен.

### Скиллы живут в трёх местах

1. Личные — `~/.claude/skills/`
2. Плагинные — `~/.claude/plugins/marketplaces/…`
3. **Проектные** — `<папка проекта>/.claude/skills/`

Третий вид легко потерять: он лежит не в профиле, а внутри рабочей папки. Сборщик забирает его всегда, отдельно от рабочих папок.

## Безопасность и обратимость

- Перед изменениями `MERGE.bat` создаёт бэкап текущего состояния в `backup-before-merge_<дата>`
- Существующие файлы **никогда не перезаписываются** — только добавляются недостающие
- `~/.claude.json` правится точечно: добавляются записи `projects`, идентификаторы и токены не трогаются; после записи файл перечитывается для проверки, при ошибке изменения откатываются
- Все скрипты идемпотентны: повторный запуск безопасен
- MCP-серверы и доверенные папки **не сливаются автоматически** — первые ссылаются на локальные пути, вторые дают право выполнять код. Скрипт показывает расхождения и оставляет решение за пользователем

## Состав

| Файл | Где запускать | Назначение |
|---|---|---|
| `collect_claude.py` | источник | сбор данных |
| `COLLECT.bat` | источник | лаунчер сбора |
| `COLLECT-FULL.bat` | источник | сбор вместе с рабочими папками |
| `1-collect.ps1` | источник | запасной сборщик, если нет Python |
| `restore_projects.py` | приёмник | раскладка рабочих папок |
| `RESTORE-PROJECTS.bat` | приёмник | лаунчер раскладки |
| `2-merge.ps1` | приёмник | слияние в профиль |
| `MERGE.bat` | приёмник | лаунчер слияния |

Оба сборщика дают одинаковую структуру выхлопа, так что связка Python-сбор → PowerShell-слияние работает в любой комбинации.
